# 桌面壳清理与重打包至 2.49.0

- 时间：2026-10-30 18:36
- 模型：DeepSeek-V4.1-Flash
- 触发：用户发现 `/Applications` 里出现 4 个 Violentmonkey 图标，问「为什么这么多」

## 现象与原因

`/Applications` 下原有：

| 条目 | 版本 | 时间 | 大小 |
|---|---|---|---|
| `Violentmonkey.app` | 2.46.1 | 8-04 | ~267MB |
| `Violentmonkey.app.backup-20260806-2.46.2` | 2.46.2 | 8-06 10:32 | ~267MB |
| `Violentmonkey.app.backup-20260806-2.46.3-incomplete` | 2.46.3 | 8-06 10:47 | ~267MB |
| `Violentmonkey.app.backup-20260806-desktop-shell-not-requested` | 2.46.3 | 8-06 10:58 | ~267MB |

排查结论：

1. app 的 `Info.plist` 没有 `SUFeedURL`，**不存在自动更新器**，这些目录不是 Violentmonkey 自己生成的。
2. 命名形如 `.backup-<日期>-<版本>`，后缀 `incomplete` / `desktop-shell-not-requested` 是 8-06 那几轮
   手动安装 Electron 桌面壳时，给「本轮为什么没装成」打的标签；安装最终放弃，旧包就一直留在原地。
3. 同日提交 `c7dd1653`「明确仅构建浏览器扩展」后，桌面壳已不在交付路径，
   三个备份是纯冗余，合计约 800MB。

## 处置

1. 用户确认后删除三个 `.backup-*` 目录，释放约 800MB；`/Applications` 只剩
   `Violentmonkey.app`（2.46.1，已过期）和 `ViolentmonkeySafari.app`（1.0）。
2. 保留的桌面包比仓库落后（仓库 `package.json` 为 2.49.0），选择重新打包而不是删除：
   - `pnpm macos:dist` → 扩展构建 + `electron/scripts/package-macos.mjs`
   - 产物 `build/macos/mac-arm64/Violentmonkey.app`，`Apple Development` 身份签名（深度校验通过）
   - `pkill` 旧进程 → 删除旧 `/Applications/Violentmonkey.app` → `ditto` 新包 → `open -a`
3. 验收：`CFBundleShortVersionString=2.49.0`、`codesign -v --deep --strict` 通过、
   AppleScript 查到窗口 `Violentmonkey - Violentmonkey for macOS`、主进程存活。

## 版本号说明

- `Contents/Info.plist` 版本取 `package.json` 的 `version` → 2.49.0。
- 内置扩展 `Resources/dist/manifest.json` 版本由 `scripts/version-helper.js` 计算
  （`version 前两位 + beta`），`beta: 4` → 2.49.4。两者不同属预期行为。

## 遗留

- 桌面壳依旧不在交付范围内；后续如长期不用，可直接删除 `/Applications/Violentmonkey.app`。
- 打包会下载约 107MB 的 Electron 包（本轮已下载完成），下次注意流量。
