# 角标 API Promise 修复（2026-09-30 00:57:26）

## 现象

在 Chrome 154 的隔离临时配置中加载 MV3 扩展，每次 service worker 启动都会抛：

```text
TypeError: Cannot read properties of undefined (reading 'catch')
    at updateState (sw.js:6827)
    at forEachTab (sw.js:3391)
```

该异常在扩展启动时为每个标签页触发一次，并导致同一函数中后续的角标、图标更新被跳过。

## 根因

`src/background/utils/icon.js` 里的 `browserAction` 用自定义包装调用 `chrome.action`/`chrome.browserAction`：为抑制 `no tab id` 之类的 `chrome.runtime.lastError`，调用时额外传了一个回调 `ignoreChromeErrors`。实测 Chrome 154 上：

- 不传回调：返回 Promise（`.then`、`.catch` 可用）；
- 传回调：返回 `undefined`。

自定义包装又没有把返回值传出去，于是 `browserAction.setTitle({...}).catch(noop)` 拿到 `undefined` 并抛 TypeError。上游 `icon.js` 直接使用 `src/common/browser.js` 的 Promise 化命名空间，因此不受影响。

## 修复

新增 `src/background/utils/action-api.js`，把四个异步方法统一包成“总是返回 Promise”，缺失 API 时返回已完成 Promise；`icon.js` 改为使用该包装。同步补充单元测试覆盖三种返回形态。

## 验证

- 修复前：扩展启动异常 1 条（重启后重复出现）。
- 修复后：同环境同版本异常 0 条。
- `run ci` 通过 12 个套件、74 个测试。

## 边界

本轮只验证了启动路径与自动化测试；角标数字、背景色、标题与图标在真实网页上的显示效果仍需要人工确认。
