# 新增「GitHub 链接在新标签页打开」用户脚本

- 时间：2026-10-14 16:51（v1.0.0）；同日追加 v1.0.1
- 产出：`脚本/github链接新标签打开.js`（v1.0.1）
- 触发需求：让 github.com 内所有网页链接点击后都在新标签页打开。

## 实现思路

1. **事件委托而非遍历 DOM**：GitHub 是 SPA（单页应用），列表、搜索结果、issue 评论等内容都是动态渲染。如果直接遍历 `a[href]` 设置 `target="_blank"`，滚动加载/翻页后新插入的链接会失效。改为在 `document` 上以**捕获阶段**监听 `click`，动态链接也能命中。
2. **抢在 SPA 路由之前**：`useCapture=true`，在 GitHub 自己的 pushState 路由之前 `preventDefault + stopPropagation`，避免它先把当前页跳走。
3. **只接管"左键无修饰键单击"**：
   - 右键（菜单）、中键（浏览器本来就新标签）、`Cmd/Ctrl/Shift/Alt+点击`（用户自己选了打开方式）一律不干预。
   - `event.defaultPrevented` 时不重复处理。
4. **排除清单**：
   - `href="#"` 或 `#xxx` 的页内锚点；
   - `javascript:` / `mailto:` / `tel:` / `blob:` / `data:` 伪协议；
   - 用户已经写死 `target="_blank"` / `_parent` / `_top` 的链接（尊重原设置）；
   - 没有 `href` 属性的 `a` 标签（按钮样式占位）。
5. **`window.open(url, "_blank", "noopener,noreferrer")`**：安全参数避免新页面通过 `window.opener` 反向控制原标签。
6. **兜底**：若 `window.open` 被弹窗拦截器挡住（返回 `null`），回退成当前标签跳转，避免点击完全无响应；调试模式下会 `console.warn`。

## 匹配范围

```
*://github.com/*
*://*.github.com/*
```

覆盖 `gist.github.com`、`raw.githubusercontent.com`、`api.github.com` 等所有子域。`api.github.com` 上几乎没有用户可点的链接，实际只影响 gist / raw 等浏览场景。

## 调试

- 脚本头部 `DEBUG = true`，每次拦截都会在控制台打印被打开的 URL 和锚点文本，便于发现误触。
- 确认无误后可改为 `false`。

## 验证

- `node --check` 语法通过。
- 待人工在 GitHub 页面实测：仓库列表、文件目录、issue 详情、gist、raw 文件页点击链接均应新标签打开；页内目录锚点、中键、Cmd+点击行为不变。

## 后续可优化方向（未做，待用户决定）

- 白名单/黑名单：例如 `raw.githubusercontent.com` 的下载类链接可能更适合当前页下载；目前是"全接管"策略。
- 同时给动态插入的 `a` 标签补 `target="_blank"`，让右键菜单"在新标签页打开"和中键行为也带 `noopener`（目前中键/右键由浏览器默认行为处理，不影响功能）。
- 可考虑把脚本迁移到 `userscripts/` 目录并加 `.user.js` 后缀，与上游示例脚本保持一致；目前放在 `脚本/` 下与既有 `x自动转帖、转帖后自动喜欢.js` 同目录。

## v1.0.1 变更（2026-10-14）

按用户确认，对下载类链接放行，保持当前页下载行为：

1. `anchor.hasAttribute('download')`：HTML5 原生 download 属性，浏览器直接下载，不接管。
2. `hostname === 'codeload.github.com'`：GitHub 仓库源码归档（zip/tar.gz）的实际下载域名，302 跳转后的真实地址。
3. `github.com` 且 `pathname` 含 `/releases/download/`：Releases 页面的二进制附件。

实现上在 `shouldIntercept` 内用 `new URL(anchor.href, location.href)` 解析绝对地址后判断 host/path；解析失败直接不接管，避免异常。其余逻辑不变。
