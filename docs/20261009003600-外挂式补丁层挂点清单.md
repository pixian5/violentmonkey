**唯一无法外挂的例外：`src/background/sync/sync-engine.js`（+45 / −25）。**

原因是它改的是模块内部状态机：授权流程的 `authAttempt` 是模块级变量，
`service.authorize()` 又直接调用同模块的 `openAuthPage()`，
ESM 的静态绑定让 fork 层无法在运行期替换。要外挂就得整体复制一份 `authorize` 命令，
反而会把上游后续改动全部挡在外面，得不偿失。

处理办法：

1. 改动处都打了 `// fork(patch):` 标记，合并冲突时一眼可见；
2. 这个文件是**已知冲突点**，合并上游后必须人工核对（见下方步骤）；
3. 这份修改本身是通用 bug 修复（并发授权竞态、tabId 误匹配、Safari 下
   `addListener(..., ['blocking'])` 抛错导致授权悬挂），**建议给上游提 PR**，
   上游一旦合入，本地这段就可以删掉。

## 顺手修掉的问题

- `vm-import.vue` 里 `showDebug` 原本**硬编码为 `true`**，设置页会一直显示调试信息行。
  现在改成默认关闭，需要时执行 `localStorage.setItem('vmImportDebug', '1')` 再打开设置页。
- `zipTimeToDate` 的运算符优先级错误：`(time >> 21) & 0x0f - 1` 实际按 `& (0x0f - 1)` 计算，
  已修正为 `((time >> 21) & 0x0f) - 1`。这是通用 bug，同样值得提给上游。

## 合并上游的标准步骤

```bash
git fetch upstream
git merge upstream/master
```

冲突处理顺序：

1. 先看是不是 `src/fork/` 之外的文件；
2. `sync-engine.js` 冲突 → 保留我们的 `authAttempt` 状态机，把上游新增逻辑并进去；
3. `vm-import.vue` / `vm-export.vue` 冲突 → 保留我们的按钮与 fork 调用，其余取上游；
4. `preinject-core.js` / `requests.js` / `download-via-api.js` 冲突 → 保留调用 fork 的那一行，其余取上游；
5. 五个入口文件的 `import '@/fork';` 必须保留；
6. 合并后跑 `pnpm run ci`（或等价的 lint + test + build）。
