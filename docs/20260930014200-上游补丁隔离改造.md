# 上游补丁隔离改造（2026-09-30 01:42:00）

## 目标

把本 fork 变成“上游的一份补丁”：自有改动尽量只以新增文件存在，上游原文件保持原样，
这样上游更新后不需要逐个重新套改。

## 采用的结构

三层，冲突面自上而下递减：

1. `src/fork/`（新增，0 冲突，共 616 行）：补丁聚合层 `index.js`、后台专用 `background.js`、
   API 补桩 `api-stubs.js`、能力 shim `safari-shims.js`、构建目标 `target.js`、
   后台命令补充 `db-extensions.js`、`chrome.action` Promise 包装 `action-api-patch.js`、
   弹窗设置入口 `popup-safari.js`、TXT 导入导出 `txt-transfer.js`、脚本解析通道 `script-import.js`。
2. 上游入口的一行 import（5 个文件各 1 行）：`src/background/index.js`、`src/background/sw.js`
   用 `@/fork/background`，`src/options/index.js`、`src/popup/index.js`、`src/confirm/index.js`
   用 `@/fork`。这一行是加载补丁的唯一入口，位置在最顶部，保证补桩先于上游模块求值。
3. 少量无法补丁化的行为分支：见下方清单。

构建层同样零上游改动：`__.TARGET` 不再由 webpack 常量注入（上游把 `__.*` 全做编译期内联，
运行期并不存在 `__` 对象），改为 Safari 打包脚本在 manifest 写 `fork.target`，
由 `src/fork/target.js` 运行期读取；Safari 清单裁剪从 `scripts/manifest-helper.js`
搬到新增的 `safari/manifest-overrides.js`。

## 补丁层职责

- `api-stubs.js`：为缺失的 `webRequest`、`notifications`、`permissions`、`windows`、
  `DataTransferItem` 补语义等价的空实现；把 `storage.local.get(undefined)` 规整为 `null`；
  缺失时补 `chrome.extension.isAllowedFileSchemeAccess`。只补缺失成员，不覆盖已有实现。
- `safari-shims.js`：给 `tabs.query` 补 `url` 过滤（Safari 不支持），
  并让 `webRequest.addEventListener` 忽略 `blocking` extraInfoSpec。
- `db-extensions.js`：用 `addOwnCommands` 追加 `ParseScriptFromStorage`、`RebuildScriptIndex`。
- `action-api-patch.js`：包装 `chrome.action` 的四个方法，保证返回 Promise，
  替代原先直接改 `icon.js` 的做法。
- `popup-safari.js`：捕获阶段拦截弹窗“设置”项与齿轮右键，改为打开扩展设置页，
  替代原先改 `popup/views/app.vue` 的做法。
- `target.js`：运行期读取 manifest 的 `fork.target`，导出 `FORK_TARGET`/`IS_SAFARI`。
